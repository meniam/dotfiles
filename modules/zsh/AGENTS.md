# Zsh Module Guidelines

## Structure

The module is stowed into the user's home directory with this layout:

```text
~/.zshrc
~/.config/zsh/
├── 00-options.zsh      # Shell options
├── 10-history.zsh      # History file and retention settings
├── 20-path.zsh         # Command search paths
├── 30-env.zsh          # Exported environment variables
├── 32-colors.zsh       # LS_COLORS and LSCOLORS palettes
├── 40-completion.zsh   # Completion initialization and cache
├── 50-plugins.zsh      # Zinit bootstrap and plugin loading
├── 60-aliases.zsh      # Shared command aliases
├── 70-functions.zsh    # Shared shell functions
├── 80-prompt.zsh       # Prompt appearance and Git status
├── 85-p10k.zsh         # Powerlevel10k settings, generated by `p10k configure`
└── 90-local.zsh        # Untracked machine-specific overrides
```

Other modules drop fragments into the same directory rather than editing files
here: `25-php.zsh` from `php85`, `26-rust.zsh` from `rust`, and
`35-ssh-agent.zsh` from `ssh`. Pick a free number when adding another one, and
keep it in the range its purpose belongs to.

`.zshrc` is a minimal interactive-shell loader. It sources the numbered files in lexical order from `${XDG_CONFIG_HOME:-$HOME/.config}/zsh/`. Its other two jobs belong to Powerlevel10k: replaying the instant prompt above every line that can produce output, and sourcing `85-p10k.zsh` at the end. That one file is skipped by the loop and sourced explicitly afterwards, because the wizard only recognizes `source "$POWERLEVEL9K_CONFIG_FILE"` in `~/.zshrc`; sourcing it from the loop instead would make every wizard run append its own line.

Both Powerlevel10k lines in `.zshrc` are written in the literal form `p10k configure` scans for. The wizard reads only `~/.zshrc` and prepends or appends its own copy of anything it does not recognize, so rewording them means a wizard run duplicates them.

## Placement Rules

- Put shell options in `00-options.zsh`.
- Keep history settings in `10-history.zsh` and command lookup paths in `20-path.zsh`.
- Put exported environment variables in `30-env.zsh`, colour palettes in `32-colors.zsh`, and completion setup in `40-completion.zsh`. `32-colors.zsh` has to stay ahead of `40-completion.zsh`, whose `list-colors` zstyle reads `LS_COLORS`.
- Keep plugin initialization in `50-plugins.zsh`, aliases in `60-aliases.zsh`, functions in `70-functions.zsh`, and prompt settings in `80-prompt.zsh`.
- Leave `85-p10k.zsh` to `p10k configure`. It is generated in full, so a hand edit there is lost on the next wizard run; keep only the theme-independent fallback prompt in `80-prompt.zsh` and machine-specific prompt changes in `.zshrc.local`.
- Use `90-local.zsh` only to load optional, untracked machine-specific overrides from `${ZDOTDIR:-$HOME}/.zshrc.local`.

## General Rules

- Store Zsh cache and history files in `${ZDOTDIR:-$HOME}/.cache/zsh/`.
- Keep shared configuration portable across macOS and Debian/Ubuntu; guard platform-specific commands or paths when needed.
- Do not add credentials, tokens, personal hostnames, or machine-specific values to tracked files; use the local override file instead.

## Commenting Rules

- Write all comments in concise English.
- Add one or two comment lines before each new configuration block explaining its purpose and user-visible effect.
- Explain non-obvious behavior, ordering requirements, platform guards, or side effects; do not restate literal syntax.
- Update or remove comments when changing the behavior they describe, and do not keep commented-out code as documentation.
